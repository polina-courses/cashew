# Cashew Local — личный форк

Личная версия приложения Cashew (бюджет, Flutter) для одного пользователя. Исходный README проекта остался как есть, этот файл описывает только то, что изменено в форке и как с ним работать.

## Как устроена доставка

- Код приложения: `budget/lib`. Тесты: `budget/test`.
- Репозиторий: `polina-courses/cashew`, основная ветка `main`.
- Сборка идёт в GitHub Actions (`build-apk.yml`). Запускается при push в `main` и в ветки `feature/**`. Ветки с другими именами (`fix/...`) сборку не запускают.
- Рабочий процесс одной правки:
  1. ветка `feature/<имя>` от `main`;
  2. push, ждём зелёный CI (сборка + тесты);
  3. `git merge --ff-only` в `main`, push;
  4. сборка `main` публикует релиз с тегом `build-N` и файлом `cashew-local-N.apk`.
- Установка на телефон: в приложении Настройки → обновление (берёт последний релиз из GitHub Releases), либо скачать APK из релиза.
- Ключи подписи хранятся в GitHub Secrets и в репозиторий не попадают. Никогда не коммитить секреты.
- Локально Flutter может быть не установлен: тогда ошибки компиляции смотреть в аннотациях проверки (`check-runs/<id>/annotations`).

## Что изменено относительно оригинала

- Убраны Pro-реклама и запросы оценки; обновление через GitHub Releases.
- Доходы не требуют категории (по умолчанию «Без категории»), валюта по умолчанию RUB, компактные шапки.
- Кнопка «+»: сначала выбор типа (расход / доход / перевод), затем форма. Новая трата по умолчанию «предстоящая», доход сразу совершённый.
- У транзакции нет заголовка, только необязательный комментарий.
- Подгруппы счёта («конверты»): цели по сумме и дате, рекомендуемое пополнение, заметки, перекладывание, списание из свободных денег, таблица распределения.
- Ссылки и контакты автора оригинала убраны из приложения (раздел «О приложении», FAQ, политика, почта, веб-версия); файл LICENSE сохранён по требованию лицензии, страница лицензий в приложении осталась.
- В форме расхода всегда выбирается подгруппа: существующая, «Свободные» или «Новая подгруппа» (создаётся при сохранении с названием расхода в категории). Для периодического расхода по умолчанию выбрана новая. Список подгрупп счёта сгруппирован по категориям и показывает, сколько нужно к концу месяца.
- Счёт категории: категория расходов и счёт — почти одна сущность. Если в форме расхода счёт вручную не выбирали, то при СОХРАНЕНИИ у категории автоматически появляется свой счёт (название = категория), расход идёт на него, а подгруппа создаётся внутри. Если счёт выбран руками (даже основной), новая категория появляется, а счёт категории не создаётся (раньше он создавался сразу при выборе категории). Правило: `struct/categoryWalletRules.dart`. Деньги приходят на общий счёт; экран «Пополнить счета категорий» (Настройки и внешний вид, а также после дохода на общий счёт) раскладывает их по счетам и подгруппам по приоритету (зарплата 2/3, аванс — остаток), суммы можно править, кнопка делает переводы и раскладку. Приоритет подгруппы задаётся при создании и в редакторе, показан в списке подгрупп. Файлы: `struct/categoryAccounts.dart`, `widgets/categoryTopUp.dart`.
- Сводка на «Обзоре» (`pages/homePage/homePageTopUpSummary.dart`): по каждому счёту категории сколько отложить с ЗП и с аванса (до 12-го: 2/3 и 1/3, с 13-го — всё с аванса) и итого по всем счетам; нажатие открывает «Пополнить счета категорий».
- Страница счёта: приоритет — значок из трёх столбиков (3/2/1 закрашено), у подгруппы строка «📅 лежит / нужно, пополнить на N» («пополнить на» бледным курсивом, сумма красным; галочка если хватает;), чипы «ЗП» и «Ав» с суммами, значок песочных часов у временных. Функция `splitNeed` (envelopePlan.dart) делит потребность: до 12-го 2/3 и 1/3, потом всё на аванс. Сводка «Всего» на главной: сумма в строке с названием, ЗП/Ав отдельной строкой под ней (длинные суммы не налезают). Строки подгрупп: «лежит / нужно» отдельной строкой, ниже «пополнить на», ЗП/Ав и срок переносятся (Wrap), не налезают друг на друга.
- Подгруппы создаются сами: расход с пометкой «Периодическая» (или подписка) попадает в календарь и в категорию, и в счёте автоматически появляется подгруппа с названием расхода (одинаковые название и категория — одна подгруппа). Есть срок окончания — подгруппа временная и удаляется, когда платежей не осталось. Категория и «временная» хранятся в настройках `envelopeMeta`.
- Доработки подгрупп: зарплата (ближайшее к 12-му) закрывает 2/3 потребности, аванс (к 25-му) — всё оставшееся; редкие платежи (раз в 3/6 месяцев, раз в год) копятся заранее равными долями к сроку; цель со сроком даёт ежемесячный взнос от остатка на начало месяца (`envelopeBase`); цель без срока получает деньги последней «по возможности»; подгруппу можно убрать в архив (остаток уходит в «Свободные», платежи остаются без подгруппы) и вернуть; закончившиеся временные подгруппы уходят в архив сами.
- Подгруппы по календарю: расписание подгруппы — это неоплаченные расходы календаря (в том числе повторяющиеся), выбравшие эту подгруппу. Потребность = платежи, которые ещё предстоят в этом календарном месяце, + взнос на цель − что уже лежит. Поступление раскладывается по приоритету подгрупп (высокий → средний → низкий), суммы подставляются и правятся руками, нехватка показывается. Деньги, не ушедшие в подгруппы, — «Свободные» счёта. Минусов нет: нехватку при оплате закрывают «Свободные»; если их нет — красное «Нет свободных денег», платёж не проводится. В начале нового месяца остатки подгрупп (без цели) уходят в «Свободные». Автосписания по дате нет: списывается только после отметки «оплачено». Приоритет и перенос хранятся в настройках (`envelopePlans`, `envelopeSweep`), схема БД не менялась.
- Календарь предстоящих платежей (слот в нижнем меню): сводка по неделе/месяцу и список по датам.
- Главная: список только совершённых операций и отдельная вкладка «Предстоящие» (от ближайших к дальним).
- Упрощённое погашение кредита: без категории и бюджета, переключатель «Со счёта / Без источника».
- Окно несохранённых изменений: «Выйти без изменений» / «Вернуться для редактирования».

## Взносы на цели

- Взнос на цель (трата с выбранной целью) уменьшает баланс конкретного счёта, но остаётся в общей сумме по всем счетам («Обзор», чистый баланс): как отдельный накопительный счёт.
- Для счёта, открытого по отдельности, взнос считается как обычная трата. Кредиты/займы работают как покупки, без изменений.
- Исправлено: проверка «цель достигнута» считала взносы по полю кредита.

## Баланс счёта меньше, чем в подгруппах

- Если баланс счёта уменьшили или обнулили, а в подгруппах деньги остались, лишнее автоматически снимается с подгрупп (`shrinkEnvelopesToWallet`): сначала с низкого приоритета, внутри приоритета пропорционально. Срабатывает при открытии страницы счёта и в `prepareEnvelopes`. Если счёт ушёл в минус, подгруппы не трогаются. Снятое запоминается (`envelopeShrunk`) и возвращается подгруппам из свободных денег, когда деньги на счёте снова появились (`restoreShrunkEnvelopes`); снятия сборок 120–126 подхватываются один раз (`importLegacyShrinks`).

## Только рубли

- Выбор валюты у счёта оставлен один: российский рубль. При каждом запуске все счета принудительно переводятся на рубль (`forceAllWalletsRuble`), счёт по умолчанию создаётся в рублях. Курсы и конвертация остаются в коде, но при одной валюте не влияют на суммы.

## Навигация и счета

- Нижнее меню: Главная, Счета, «+» посередине, Календарь, ЖКХ. Настройки («Ещё») открываются шестерёнкой на главной и на вкладке «Счета» (стек-индексы: 0 главная, 20 счета, 18 календарь, 19 ЖКХ; `bottomNavBar.dart`, `pages/homePage/newHomePage.dart`, `pages/walletsTabPage.dart`).
- Количество транзакций в карточках и списках счетов не показывается: есть общий журнал (категория, счёт списания, дата и время).

## Перевод баланса

- В окне перевода получатель выбирается переключателем «Счёт / Цель / Кредит». Цель: взнос (расход со счёта с `objectiveFk`). Кредит: платёж (расход со счёта с `objectiveLoanFk`), долг уменьшается. Логика: `struct/transferTarget.dart`, тесты `test/transfer_and_category_wallet_test.dart`.

## Кредиты

- Кредит — отдельный долг: при оформлении НЕ создаётся запись ни на одном счёте (сумма хранится в самом кредите, учитывается в итогах долгов). Гасить его можно платежами с любого счёта.
- Новый кредит или цель по умолчанию привязывается к общему счёту, а не к тому, что выбран на главной (раньше первоначальная запись кредита могла списаться со счёта категории).
- При удалении кредита с записями спрашивается: «Удалить с записями» (деньги на счетах возвращаются как было) или «Оставить записи» (они становятся обычными расходами/доходами, как раньше).

## Сводка «Обзор»

- Карточка «Нужно отложить на счета категорий» на главной — таблица: Счёт | ЗП | Ав | Итого, внизу строка «Всего». Суммы выровнены по правому краю и в своих колонках, не прыгают.

## Форма расхода и дохода

- Сумма вводится прямо в форме (поле сверху, цифровая клавиатура), отдельного окна для суммы нет. Расход: сумма → название → категория → счёт и подгруппа → дополнительно. Доход: сумма → название → счёт → дата и комментарий. Цепочка окон (категория → сумма) убрана; для старой формы (переводы, кредиты) окно суммы осталось.

## ЖКХ

- Страница «ЖКХ»: пятая иконка нижнего меню (между тремя настраиваемыми и «Ещё»; стек-индекс 19, `bottomNavBar.dart`), также «Ещё» → «ЖКХ»: свои пункты (название, обычная сумма за месяц), кружок «оплачено» раз в месяц; сама сбрасывается 1 числа (оплата считается текущей, только если месяц совпадает). Снять отметку можно повторным нажатием.
- Переплата: при отметке вводится сколько оплачено; разница с обычной суммой записывается в баланс пункта (плюс — переплата, минус — недоплата). В следующем месяце «к оплате» = сумма − переплата (не меньше 0). Баланс можно поправить вручную в карточке пункта.
- Данные в настройках (ключ `utilities`), логика в `budget/lib/struct/utilities.dart`, тесты `budget/test/utilities_test.dart`. Транзакции по отметке не создаются.

## Правила

- Если нашли ошибку, сначала воспроизвести тестом (`budget/test`), потом чинить.
- Меняя схему БД, поднимать `schemaVersionGlobal` в `tables.dart` и добавлять миграцию.
- Не переписывать чужие коммиты в ветке без согласования.
